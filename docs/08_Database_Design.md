### 1. วัตถุประสงค์
เอกสารฉบับนี้กำหนดโครงสร้างฐานข้อมูล (Database Schema) ของระบบ "ลาดพร้าวสร้างสุข" โดยใช้ **Google Sheets** เป็นฐานข้อมูลหลัก เพื่อใช้เป็นมาตรฐานในการเขียนสคริปต์ Backend (Google Apps Script) และการดึงข้อมูลไปแสดงผลบน Frontend

--------------------------------------------------------------------------------

### 2. ภาพรวมฐานข้อมูล
ระบบจัดเก็บข้อมูลในรูปแบบตาราง (Sheet) ภายใน Google Spreadsheet โดยแบ่งออกเป็นตารางหลักสำหรับบริหารจัดการข้อมูลผู้ใช้ กิจกรรม และการดำเนินงานของระบบ

*   **Database Tool:** Google Sheets
*   **Sheet URL:** [เชื่อมต่อตามพารามิเตอร์ระบบ]
*   **Primary Key:** โดยปกติจะใช้ `User_ID` หรือรหัสที่ระบบสร้างขึ้นอัตโนมัติในคอลัมน์แรก

--------------------------------------------------------------------------------

### 3. รายละเอียดตาราง (Table Schemas)

#### 3.1 ตาราง Users (ข้อมูลบุคลากร)
ใช้เก็บข้อมูลส่วนบุคคลและข้อมูลสุขภาพเบื้องต้น
| คอลัมน์ | คำอธิบาย | หมายเหตุ |
| :--- | :--- | :--- |
| `User_ID` | รหัสผู้ใช้งาน (เลขบัตรประชาชน) | Primary Key |
| `Full_Name` | ชื่อ-นามสกุล | |
| `Nickname` | ชื่อเล่น | |
| `Position` | ตำแหน่งงาน | |
| `Department` | ฝ่าย/ส่วนราชการ | มี 11 ฝ่าย |
| `Birth_Date` | วัน/เดือน/ปีเกิด (พ.ศ.) | |
| `Gender` | เพศกำเนิด/เพศสภาพ | |
| `Weight` / `Height` | น้ำหนัก (kg) / ส่วนสูง (cm) | ใช้คำนวณ BMI |
| `BMI_Value` | ค่าดัชนีมวลกาย | |
| `Waist_Inch` | รอบเอว (นิ้ว) | |
| `Role` | บทบาท (Admin, Executive, Head, Employee) | |
| `Password` | รหัสผ่าน (Hashed) | อย่างน้อย 6 ตัวอักษร |

#### 3.2 ตาราง Steps_Log (บันทึกก้าวเดิน)
| คอลัมน์ | คำอธิบาย | หมายเหตุ |
| :--- | :--- | :--- |
| `Record_ID` | รหัสบันทึก | Auto-generated |
| `User_ID` | รหัสผู้ใช้งาน | Foreign Key |
| `Date` | วันที่นับก้าว | รูปแบบ พ.ศ. |
| `Steps` | จำนวนก้าว | |
| `Method` | วิธีบันทึก (Google Fit / Manual OCR) | |
| `Image_URL` | ลิงก์รูปภาพหลักฐานใน Google Drive | |
| `Status` | สถานะ (Pending / Approved / Rejected) | |
| `Week_No` | สัปดาห์ที่ (Week of Year) | สำหรับรายงานรายสัปดาห์ |

#### 3.3 ตาราง Sweet_Free (กิจกรรมงดน้ำหวาน)
| คอลัมน์ | คำอธิบาย | หมายเหตุ |
| :--- | :--- | :--- |
| `Entry_ID` | รหัสบันทึก | |
| `User_ID` | รหัสผู้ใช้งาน | |
| `Date` | วันพุธที่บันทึก | |
| `Status` | สถานะ (🟢 งดได้ / 🔴 งดไม่ได้) | |
| `Recorded_By` | ผู้บันทึก (เจ้าหน้าที่ นสส.) | |

#### 3.4 ตาราง Training & Registration (การอบรม)
*   **Training_Courses:** เก็บชื่อหลักสูตร, วัน-เวลา, สถานที่, จำนวนที่นั่ง
*   **Training_Attendance:** เก็บ `Course_ID`, `User_ID`, และสถานะการเช็กชื่อเข้าเรียน

#### 3.5 ตาราง Happy_Connect (การจับคู่บัดดี้)
| คอลัมน์ | คำอธิบาย | หมายเหตุ |
| :--- | :--- | :--- |
| `Match_ID` | รหัสการจับคู่ | |
| `User1_ID` / `User2_ID` | รหัสผู้ถูกจับคู่ (ต่างฝ่าย) | |
| `Date` | วันที่สุ่มจับคู่ | |
| `Mission_ID` | ภารกิจประจำสัปดาห์ที่ได้รับ | |
| `Status` | สถานะ (Waiting / Completed / Cancelled) | |
| `Photo_URL` | ลิงก์รูปภาพยืนยันการทำภารกิจ | |

#### 3.6 ตารางอื่น ๆ
*   **News:** หัวข้อ, เนื้อหาข่าว, ลิงก์รูปภาพ (สูงสุด 10 รูป), วันที่เผยแพร่
*   **Wellness_Meter:** ผลประเมินความสุขและความเครียดประจำวัน
*   **Voice_Executive:** ประเภทข้อความ, เนื้อหา, สถานะการตรวจสอบ, การระบุตัวตน (Anonymous)
*   **Audit_Log:** วันเวลา, ผู้กระทำ, การกระทำ (Action), รายละเอียดการเปลี่ยนแปลง

### 4. การจัดเก็บไฟล์ (File Storage Strategy)
ไฟล์สื่อทั้งหมดจะถูกเก็บไว้ใน **Google Drive** โดยระบบจะเก็บเพียง **URL** หรือ **File ID** ไว้ใน Google Sheets:
*   **Folder Structure:** แยกโฟลเดอร์ตามประเภท เช่น `Steps_Images/`, `News_Photos/`, `Reports/`
*   **Naming Convention:** ตั้งชื่อไฟล์ตามรูปแบบ `Type_User_Date.jpg` เพื่อความเป็นระเบียบ

--------------------------------------------------------------------------------

### 5. ข้อกำหนดและความปลอดภัย
*   **Data Consistency:** การแก้ไขข้อมูลสำคัญต้องถูกบันทึกใน Audit Log เสมอ
*   **Integrity:** ข้อมูลจำนวนก้าวที่ดึงจาก Google Fit จะถูกล็อคไม่ให้แก้ไข
*   **Privacy:** ข้อมูลในตาราง Voice_Executive ที่เลือกไม่ระบุตัวตน จะต้องไม่ถูกเชื่อมโยงกลับไปยังตาราง Users ในหน้าแสดงผล
