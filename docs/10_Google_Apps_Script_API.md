### 1. วัตถุประสงค์
เอกสารฉบับนี้กำหนดโครงสร้างและหน้าที่ของระบบหลังบ้าน (Backend) ซึ่งใช้ **Google Apps Script (GAS)** พัฒนาเป็น **REST API** เพื่อทำหน้าที่ประมวลผลลอจิกทางธุรกิจ จัดการฐานข้อมูล Google Sheets และควบคุมการจัดเก็บไฟล์ใน Google Drive สำหรับระบบ "ลาดพร้าวสร้างสุข"

--------------------------------------------------------------------------------

### 2. รูปแบบการทำงาน (API Implementation)
ระบบใช้ฟังก์ชันมาตรฐานของ GAS ในการรับและส่งข้อมูลในรูปแบบ **JSON**:
*   **doGet(e):** ใช้สำหรับการดึงข้อมูล (Read Operations) เช่น การเรียกดู Dashboard, รายชื่อบุคลากร, หรือประวัติการนับก้าว
*   **doPost(e):** ใช้สำหรับการบันทึกหรือแก้ไขข้อมูล (Create/Update Operations) เช่น การลงทะเบียน, การอัปโหลดรูปภาพนับก้าว และการส่งข้อเสนอแนะ

--------------------------------------------------------------------------------

### 3. โมดูลหลักของ API (Core API Modules)

#### 3.1 Authentication & User Management
*   **Registration API:** รองรับการบันทึกข้อมูลลงทะเบียน 5 ขั้นตอน โดยรับข้อมูลส่วนตัวและข้อมูลสุขภาพ (BMI) บันทึกลงตาราง `Users`
*   **Login API:** ตรวจสอบรหัสผ่าน (Hashed) และคืนค่า User Role พร้อมข้อมูลพื้นฐานกลับไปยัง Frontend

#### 3.2 Health & Activity Tracking
*   **Step Log API:** 
    *   รับข้อมูลจำนวนก้าวจาก Google Fit API โดยตรง
    *   รับภาพถ่ายแคปหน้าจอ แปลงเป็น Base64 และบันทึกลง Google Drive
*   **Sweet-Free API:** จัดการสถานะการงดน้ำหวานประจำวันพุธ (งดได้/ไม่ได้) โดยอ้างอิงจากรหัสบุคลากรรายฝ่าย

#### 3.3 Wellness & Social Hub
*   **Happy Connect API:** ทำหน้าที่สุ่มจับคู่บุคลากรต่างฝ่ายในทุกเช้าวันจันทร์ และบันทึกสถานะภารกิจ
*   **Wellness Assessment API:** รับค่าจาก Happy/Stress Meter และบันทึกลงชีทเพื่อนำไปประมวลผล Dashboard
*   **Voice to Executive API:** จัดการการส่งข้อความถึงผู้บริหาร โดยรองรับโหมด "ไม่ระบุตัวตน" (Anonymous)

--------------------------------------------------------------------------------

### 4. การเชื่อมต่อบริการภายนอก (System Integration)
GAS ทำหน้าที่เป็นตัวกลางในการสื่อสารกับบริการอื่น:
*   **Gemini OCR Integration:** เมื่อมีการอัปโหลดรูปภาพก้าวเดิน API จะส่งไฟล์ภาพไปยัง **Gemini 1.5 Pro/Flash** เพื่อสกัดตัวเลขจำนวนก้าวกลับมาบันทึก
*   **LINE OA Notification:** ส่งคำสั่งกระจายข่าวสาร (Broadcast) หรือแจ้งเตือนคู่บัดดี้ (Happy Connect) ผ่าน LINE Messaging API
*   **Google Fit API:** เชื่อมต่อเพื่อดึงสถิติสุขภาพโดยตรง (ล็อคข้อมูลไม่ให้แก้ไข)

--------------------------------------------------------------------------------

### 5. การจัดการไฟล์ใน Google Drive
GAS จัดระเบียบการจัดเก็บไฟล์เพื่อความเป็นระเบียบและประหยัดพื้นที่:
*   **Folder Mapping:** แยกโฟลเดอร์ตามประเภทกิจกรรม (เช่น `Step_Proofs`, `News_Images`, `Reports_PDF`)
*   **File Naming:** ตั้งชื่อไฟล์โดยใช้รูปแบบ `Activity_UserID_Date.jpg` เพื่อให้ง่ายต่อการตรวจสอบย้อนหลัง
*   **Direct View Link:** แปลงไฟล์ ID เป็น URL เพื่อให้ Frontend นำไปแสดงผลบนหน้าจอได้ทันที

--------------------------------------------------------------------------------

### 6. ความปลอดภัยและการตรวจสอบ (Security & Audit)
*   **Endpoint Protection:** ตรวจสอบสิทธิ์ (Authentication Token) ทุกครั้งก่อนเข้าถึง API
*   **Input Validation:** ตรวจสอบความถูกต้องของข้อมูลก่อนบันทึกลง Google Sheets เพื่อป้องกัน Bug
*   **Audit Log Execution:** ทุกการกระทำที่มีความสำคัญ (เช่น การอนุมัติก้าวเดินหรือการลบข้อมูล) GAS จะบันทึกประวัติลงในชีท `Audit_Log`
*   **PDPA Compliance:** เข้ารหัสข้อมูลที่อ่อนไหวและไม่ส่งข้อมูลส่วนบุคคลที่เกินความจำเป็นกลับไปยัง Client
