### 1. วัตถุประสงค์
เอกสารฉบับนี้กำหนดรายละเอียดการเชื่อมต่อและการทำงานร่วมกันระหว่างระบบ "ลาดพร้าวสร้างสุข" กับ **LINE Official Account (LINE OA)** เพื่อใช้เป็นเครื่องมือหลักในการแจ้งเตือน (Notifications) การสื่อสารข้อมูล และการสร้างปฏิสัมพันธ์กับบุคลากรสำนักงานเขตลาดพร้าวได้อย่างรวดเร็วและทั่วถึง

--------------------------------------------------------------------------------

### 2. ข้อมูลทางเทคนิค (Technical Specifications)
การเชื่อมต่อใช้ **LINE Messaging API** โดยมีข้อมูลพารามิเตอร์หลักดังนี้:
*   **Technology:** LINE Messaging API + Webhook
*   **Backend Interface:** Google Apps Script (GAS) ทำหน้าที่รับ-ส่งข้อมูลผ่าน API
*   **Authentication:** ใช้ Channel Secret และ Channel Access Token (Long-lived) ที่ระบุไว้ในระบบรักษาความปลอดภัย

--------------------------------------------------------------------------------

### 3. ฟีเจอร์หลัก (Core Integration Features)

#### 3.1 การกระจายข่าวสาร (Broadcast Messaging)
*   เมื่อผู้ดูแลระบบ (นสส.) สร้างข่าวประชาสัมพันธ์ใหม่ในโมดูลจัดการข่าวสาร ระบบจะมีสวิตช์เลือก "ส่ง Notification ไปยัง Line OA อัตโนมัติ"
*   รองรับการส่งข่าวสารพร้อมรูปภาพ (สูงสุด 10 รูป)

#### 3.2 การแจ้งเตือนกิจกรรม Happy Connect
*   **การแจ้งเตือนจับคู่:** เมื่อระบบสุ่มจับคู่ Buddy ต่างฝ่ายสำเร็จในทุกเช้าวันจันทร์ ระบบจะส่งข้อความแจ้งเตือนไปยังผู้ใช้ทั้งคู่โดยตรง
*   **การทักทาย:** ภายในแอปจะมีปุ่ม [💬 ทักทายผ่าน Line OA] เพื่อให้คู่ Buddy สามารถเริ่มต้นบทสนทนาและนัดหมายภารกิจได้ทันที

#### 3.3 การลงทะเบียนและยืนยันตัวตน
*   ใช้ LINE OA ในการส่งข้อความต้อนรับ (Welcome Message) พร้อมลิงก์ไปยังหน้าลงทะเบียนสำหรับสมาชิกใหม่
*   ใช้สำหรับการแจ้งเตือนเมื่อข้อมูลก้าวเดินที่อัปโหลดผ่านภาพถ่าย (OCR) ได้รับการตรวจสอบและอนุมัติแล้ว

### 4. สถาปัตยกรรมความปลอดภัย (Security Architecture)
ตามมาตรฐานความปลอดภัยของโครงการ ข้อมูลสำคัญของการเชื่อมต่อ LINE จะต้องได้รับการจัดการดังนี้:
*   **Environment Variables:** ห้ามเก็บ Channel Secret และ Access Token ไว้ในซอร์สโค้ด (Hardcode) แต่ให้เก็บไว้ใน `.env.local` สำหรับการพัฒนา และตั้งค่าใน **Vercel Environment Variables** สำหรับการใช้งานจริง
*   **Data Protection:** ข้อมูลส่วนบุคคลที่ส่งผ่าน LINE ต้องเป็นไปตามหลัก PDPA โดยส่งเฉพาะข้อมูลที่จำเป็นต่อการใช้งานเท่านั้น

--------------------------------------------------------------------------------

### 5. ขั้นตอนการทำงานของ Webhook (Integration Workflow)
1.  **Frontend/Admin Action:** ผู้ใช้หรือผู้ดูแลระบบกระทำการในแอป (เช่น ประกาศข่าว หรือ ยืนยันกิจกรรม)
2.  **GAS API Processing:** ระบบหน้าบ้านส่งคำขอไปยัง Google Apps Script
3.  **LINE API Call:** GAS เรียกใช้บริการ LINE Messaging API เพื่อส่งข้อความแจ้งเตือนไปยังสมาชิก
4.  **User Interaction:** สมาชิกได้รับแจ้งเตือนบนมือถือ และสามารถกดลิงก์ใน LINE เพื่อกลับเข้าสู่แอปพลิเคชันได้ทันที
