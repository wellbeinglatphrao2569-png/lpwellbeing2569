### 1. วัตถุประสงค์
เอกสารฉบับนี้กำหนดมาตรฐานและนโยบายด้านความปลอดภัย (Security) และการคุ้มครองข้อมูลส่วนบุคคล (Privacy) ตามหลัก **PDPA** สำหรับระบบ "ลาดพร้าวสร้างสุข" เพื่อสร้างความมั่นใจให้แก่บุคลากรสำนักงานเขตลาดพร้าวว่าข้อมูลสุขภาพและข้อมูลส่วนบุคคลจะได้รับการดูแลอย่างปลอดภัยและถูกนำไปใช้ตามวัตถุประสงค์ของโครงการเท่านั้น

--------------------------------------------------------------------------------

### 2. การจัดการการเข้าถึงและการยืนยันตัวตน (Identity & Access Management)
*   **Authentication:** ระบบกำหนดให้ผู้ใช้เข้าสู่ระบบด้วย **เลขบัตรประชาชนและรหัสผ่าน** โดยรหัสผ่านต้องมีความยาวอย่างน้อย 6 ตัวอักษรและถูกจัดเก็บในรูปแบบการเข้ารหัส (Hashed Password) เพื่อความปลอดภัย
*   **Registration Flow:** บุคลากรต้องผ่านขั้นตอนการลงทะเบียนและยืนยันตัวตนก่อนใช้งานครั้งแรก เพื่อตรวจสอบความถูกต้องของข้อมูลเบื้องต้น
*   **Role-Based Access Control (RBAC):** จำกัดสิทธิ์การเข้าถึงข้อมูลตามบทบาทของผู้ใช้งาน (Admin, Executive, Department Head, Employee)
    *   **ผู้บริหาร:** เข้าถึง Dashboard และรายงานเชิงบริหารได้เพิ่มเติม
    *   **ผู้ดูแลระบบ (นสส.):** มีสิทธิ์จัดการข้อมูลสมาชิก กิจกรรม และการตั้งค่าระบบทั้งหมด

--------------------------------------------------------------------------------

### 3. การคุ้มครองข้อมูลส่วนบุคคล (PDPA Compliance)
*   **Purpose Limitation:** ข้อมูลส่วนบุคคล (เช่น ชื่อ-สกุล, วันเกิด, เพศ) และข้อมูลสุขภาพ (เช่น น้ำหนัก, ส่วนสูง, BMI, รอบเอว) จะถูกจัดเก็บและประมวลผลเพื่อวัตถุประสงค์ในการสร้างเสริมสุขภาวะภายในองค์กรเท่านั้น
*   **Data Minimization:** ระบบจะส่งเฉพาะข้อมูลที่จำเป็นต่อการใช้งานผ่านช่องทางภายนอก เช่น ข้อมูลที่ส่งผ่าน LINE OA ต้องเป็นไปตามหลัก PDPA และไม่เปิดเผยข้อมูลที่อ่อนไหวเกินจำเป็น
*   **Anonymity in Feedback:** ในโมดูล **Voice to Executive** ผู้ใช้งานสามารถเลือกส่งข้อความแบบ **"ไม่ระบุตัวตน" (Anonymous)** ได้ เพื่อคุ้มครองความเป็นส่วนตัวและความปลอดภัยของผู้ให้ข้อมูล

--------------------------------------------------------------------------------

### 4. ความปลอดภัยของระบบและข้อมูล (System Security)
*   **API Security:** ทุกการเชื่อมต่อระหว่าง Frontend และ Backend (Google Apps Script) ต้องมีระบบ Validation ตรวจสอบข้อมูลก่อนการบันทึกทุกครั้ง
*   **Secrets Management:** ข้อมูลสำคัญ เช่น API Keys, Line Channel Secret และ Access Token จะถูกเก็บไว้ใน **Environment Variables ของ Vercel** เท่านั้น ห้ามใส่ไว้ในซอร์สโค้ดหรือ Prompt โดยเด็ดขาด
*   **Data Integrity:** ข้อมูลสุขภาพที่สำคัญ เช่น จำนวนก้าวที่ดึงจาก Google Fit API จะถูกล็อคไม่ให้ผู้ใช้งานแก้ไขตัวเลขด้วยตนเอง เพื่อรักษาความถูกต้องของข้อมูล

--------------------------------------------------------------------------------

### 5. การตรวจสอบและความโปร่งใส (Accountability)
*   **Audit Log:** ระบบจะบันทึกประวัติการกระทำของผู้ดูแลระบบ (Admin) ทุกครั้ง เช่น ใครเป็นผู้อนุมัติผลก้าวเดิน, ใครแก้ไขข้อมูลบุคลากร หรือใครเป็นผู้สร้างรายงาน เพื่อให้สามารถตรวจสอบย้อนหลังได้
*   **Data Verification:** สำหรับกิจกรรมนับก้าวที่อัปโหลดผ่านภาพถ่าย เจ้าหน้าที่ นสส. จะต้องเป็นผู้ตรวจสอบความถูกต้องก่อนการอนุมัติผลเข้าระบบ

--------------------------------------------------------------------------------

### 6. การสำรองและกู้คืนข้อมูล (Backup & Continuity)
*   **Backup Strategy:** ผู้ดูแลระบบสามารถสำรองข้อมูลจาก Google Sheet และส่งออกเป็นไฟล์ Excel ได้ เพื่อลดความเสี่ยงจากการสูญหายหรือการแก้ไขข้อมูลที่ผิดพลาด
*   **Cloud Storage:** ไฟล์รูปภาพและเอกสารสำคัญจะถูกจัดเก็บอย่างปลอดภัยใน Google Drive ของโครงการ
