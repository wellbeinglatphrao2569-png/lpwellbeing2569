### 1. วัตถุประสงค์
เอกสารฉบับนี้มีวัตถุประสงค์เพื่อกำหนดกลยุทธ์ ขอบเขต และขั้นตอนการทดสอบระบบ (Test Plan) เพื่อให้มั่นใจว่าเว็บแอปพลิเคชันทำงานได้อย่างมีเสถียรภาพ ปลอดภัย และตรงตาม Business Logic ของโครงการสร้างสุขภาวะองค์กรก่อนเปิดใช้งานจริง

--------------------------------------------------------------------------------

### 2. ขอบเขตการทดสอบ (Testing Scope)
ครอบคลุมการทดสอบ 10 โมดูลหลัก (FR-01 ถึง FR-10) บนสภาพแวดล้อมที่เชื่อมต่อกับ Google Workspace จริง

#### 2.1 การทดสอบระดับโมดูล (Functional Testing)
*   **ระบบลงทะเบียน 5 ขั้นตอน:** ทดสอบการคำนวณ BMI อัตโนมัติและการบันทึกข้อมูลลง Google Sheet
*   **ระบบนับก้าว:** ทดสอบการดึงข้อมูลจาก Google Fit และความแม่นยำของ Gemini AI OCR ในการอ่านค่าจากรูปภาพ
*   **Happy Connect:** ทดสอบลอจิกการสุ่มคู่บัดดี้แบบต่างฝ่าย (Cross-Department) และระบบยืนยันกิจกรรมคู่
*   **ระบบการอบรม:** ทดสอบการจองที่นั่งแบบ Real-time และสิทธิ์การเช็กชื่อเฉพาะเจ้าหน้าที่ นสส. [46, 14-1 (History)]
*   **ระบบรายงาน:** ทดสอบการส่งออกไฟล์ PDF ขนาด A4 และความถูกต้องของข้อมูลในตาราง [49, 16 (History)]

### 3. สถานการณ์การทดสอบที่สำคัญ (Key Test Scenarios)

| ID | หัวข้อการทดสอบ | ผลลัพธ์ที่คาดหวัง |
| :--- | :--- | :--- |
| TS-01 | การเข้าสู่ระบบ | บุคลากรใช้เลขบัตรประชาชนและรหัสผ่านเข้าสู่ระบบได้ถูกต้องตามบทบาท |
| TS-02 | การบันทึกก้าว (OCR) | AI อ่านตัวเลขจากภาพและบันทึกรูปภาพลง Google Drive ได้ถูกต้อง |
| TS-03 | Happy Connect | ระบบสุ่มคู่บัดดี้เฉพาะคนที่อยู่ "ต่างฝ่าย" กันเท่านั้น |
| TS-04 | การเช็กชื่ออบรม | เฉพาะ Admin เท่านั้นที่เห็นปุ่มเช็กชื่อ และคะแนนเพิ่มให้เฉพาะผู้ที่มาจริง [14-1 (History)] |
| TS-05 | Voice to Executive | การส่งข้อความแบบ Anonymous ต้องไม่แสดงชื่อผู้ส่งในหน้า Dashboard ผู้บริหาร |
| TS-06 | สภาพแวดล้อม UI | แสดงผลภาษาไทย 100%, ปี พ.ศ. และรองรับ Responsive (Mobile First) |

### 4. การทดสอบด้านประสิทธิภาพและสถาปัตยกรรม (Non-Functional Testing)
*   **Performance:** ทดสอบการโหลดหน้าเว็บต้องไม่เกิน 3 วินาที และรองรับผู้ใช้งานพร้อมกันอย่างน้อย 500 คน
*   **Security:** ทดสอบระบบสิทธิ์ (RBAC) เพื่อให้มั่นใจว่าบุคลากรทั่วไปไม่สามารถเข้าถึงหน้า Admin หรือรายงานผู้บริหารได้ [12, 18 (History)]
*   **Integration:** ทดสอบการเชื่อมต่อ API ระหว่าง Vercel (Frontend) และ Google Apps Script (Backend)
*   **PDPA Compliance:** ตรวจสอบว่ามีการขอความยินยอม (Consent) และไม่มีการเปิดเผยข้อมูลสุขภาพที่อ่อนไหวสู่สาธารณะ [12, 18 (History)]

### 5. เกณฑ์การยอมรับ (Acceptance Criteria)
โครงการจะถือว่าผ่านการทดสอบเมื่อ:
1.  ฟังก์ชันหลักทั้งหมดทำงานได้ตาม Functional Requirements
2.  ข้อมูลใน Google Sheets และไฟล์ใน Google Drive ถูกต้องและครบถ้วน
3.  สามารถสร้างรายงาน PDF A4 ได้ตรงตามรูปแบบเอกสารราชการที่กำหนด [16 (History), 88]
4.  ไม่พบข้อผิดพลาดระดับรุนแรง (Critical Bugs) ที่ส่งผลต่อการบันทึกข้อมูลสุขภาพ
