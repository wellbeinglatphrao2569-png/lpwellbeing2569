### 1. วัตถุประสงค์
เอกสารฉบับนี้กำหนดมาตรฐานการเขียนโค้ด (Coding Standards) และระเบียบปฏิบัติในการพัฒนาซอฟต์แวร์สำหรับโครงการ "ลาดพร้าวสร้างสุข" เพื่อให้ทีมพัฒนาและ AI Agent (OpenCode) ผลิตโค้ดที่มีโครงสร้างสม่ำเสมอ ปลอดภัย และง่ายต่อการขยายผลในอนาคต

--------------------------------------------------------------------------------

### 2. หลักการพัฒนาหลัก (Core Principles)
นักพัฒนาและ AI ต้องยึดถือหลักการดังต่อไปนี้อย่างเคร่งครัด:
*   **Clean Architecture & SOLID:** การออกแบบโครงสร้างที่แยกส่วนหน้าที่ชัดเจน
*   **DRY (Don't Repeat Yourself):** หลีกเลี่ยงการเขียนโค้ดซ้ำซ้อนโดยการสร้าง Function หรือ Component ส่วนกลาง
*   **KISS (Keep It Simple, Stupid):** เน้นการเขียนโค้ดที่เรียบง่าย เข้าใจได้ทันที ไม่ซับซ้อนเกินความจำเป็น
*   **Secure by Default:** คำนึงถึงความปลอดภัยของข้อมูลตั้งแต่บรรทัดแรกที่เขียน
*   **Type Safety:** ใช้ TypeScript ในการควบคุมประเภทข้อมูลเพื่อลดข้อผิดพลาดในขณะรันไทม์

--------------------------------------------------------------------------------

### 3. มาตรฐานภาษาและการตั้งชื่อ (Naming Conventions)
*   **ภาษาในโค้ด:** ใช้ภาษาอังกฤษสำหรับการตั้งชื่อตัวแปร ฟังก์ชัน และคลาส
*   **ภาษาใน UI:** ข้อความที่แสดงผลให้ผู้ใช้เห็น (Labels, Buttons, Messages) ต้องเป็น **ภาษาไทย 100%**
*   **Component & File Names:** ใช้รูปแบบ **PascalCase** (เช่น `SidebarNavigation.tsx`, `StepLogTable.tsx`)
*   **Variables & Functions:** ใช้รูปแบบ **camelCase** (เช่น `calculateBmi`, `userData`)
*   **Constants:** ใช้รูปแบบ **UPPER_SNAKE_CASE** (เช่น `GAS_API_URL`, `MAX_STEP_GOAL`)
*   **Folders:** ใช้รูปแบบ **kebab-case** สำหรับชื่อโฟลเดอร์ในโปรเจกต์ Next.js

--------------------------------------------------------------------------------

### 4. มาตรฐาน Frontend (Next.js & TypeScript)
*   **Framework:** ใช้ Next.js (App Router) เป็นโครงสร้างหลัก
*   **Components:** ต้องออกแบบให้สามารถนำกลับมาใช้ซ้ำได้ (Reusable Components) และมีการแยก Logic ออกจาก UI
*   **Styling:** ใช้ Tailwind CSS ร่วมกับ DaisyUI และยึดตามมาตรฐานการดีไซน์แบบ Futuristic Clean
*   **Props:** ทุก Component ต้องมีการกำหนด TypeScript Interface สำหรับ Props เสมอ

--------------------------------------------------------------------------------

### 5. มาตรฐาน Backend (Google Apps Script)
*   **REST API:** พัฒนา GAS ให้ทำหน้าที่เป็น REST API ผ่านฟังก์ชัน `doGet` และ `doPost`
*   **Validation:** ทุก API Endpoint ต้องมีการตรวจสอบความถูกต้องของข้อมูล (Input Validation) ก่อนบันทึกลง Google Sheets
*   **Error Handling:** ต้องมีระบบ Try-Catch และส่งคืนข้อความแสดงข้อผิดพลาดในรูปแบบ JSON ที่สื่อความหมายชัดเจน

--------------------------------------------------------------------------------

### 6. ความปลอดภัยและข้อมูลสำคัญ (Security & Secrets)
*   **No Hardcoding:** ห้ามเขียนข้อมูลสำคัญ (เช่น API Key, Token, URL) ลงในซอร์สโค้ดโดยตรง
*   **Environment Variables:** ข้อมูลความลับทั้งหมดต้องเก็บไว้ในไฟล์ `.env` สำหรับการพัฒนา และตั้งค่าใน Vercel Environment Variables สำหรับการใช้งานจริง
*   **Data Protection:** ปฏิบัติตามหลัก PDPA โดยเฉพาะข้อมูลสุขภาพ (น้ำหนัก, ส่วนสูง, โรคประจำตัว) ต้องเข้าถึงได้ตามสิทธิ์ที่กำหนดเท่านั้น

--------------------------------------------------------------------------------

### 7. รูปแบบข้อมูลพิเศษ (Special Formatting)
*   **ปีปฏิทิน:** การแสดงผลในหน้าจอผู้ใช้งานทั้งหมดต้องใช้ **ปี พ.ศ.**
*   **วันที่:** ใช้รูปแบบวันที่ภาษาไทยเต็มรูปแบบ (เช่น วันพุธที่ 27 มิถุนายน พ.ศ. 2569)
*   **ตัวเลข:** จำนวนก้าวต้องมีการคั่นด้วยคอมม่า (Comma separated) เช่น 3,500 ก้าว
